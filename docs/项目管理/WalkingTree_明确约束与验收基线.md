# WalkingTree 明确约束与验收基线

## 用途

这份文档记录用户已经明确确认过、后续不得漂移的 WalkingTree 设计限制。

从现在开始：

- 如果模型截图、游戏内效果、临时分析、口头表述彼此冲突，**以本文件为准**。
- 每一轮 WalkingTree 建模、动画、审计、预览、进游戏测试前，必须先对照本文件。
- 未经用户重新确认，不得擅自放宽或改写这里的约束。

## 核心概念

### 1. 行走树首先是一整棵树

- 主体读感必须首先是“一棵活化的树”，不是树皮人形怪。
- 结构中心是：
  - 树冠
  - 树干
  - 树干下部外扩的根颈/板根
  - 多根支撑根
  - 普通次级根
  - 前侧两根较长攻击根

### 2. 底部多根支撑根就是它的腿

这是当前最重要的硬约束。

- 行走树不是靠隐藏的两条腿行走。
- 行走树也不是“很多根负责装饰，只有两条根真在走”。
- **支撑整棵树行走的，就是底部多根支撑根本身。**

必须满足：

- 至少有 **4 到 6 根可见主支撑根**。
- 这些支撑根要从树干/根颈体系中连续长出。
- 它们必须明显低于普通次级根层，形成“腿”的读感。
- 它们要共同承担支撑与步态，而不是只有个别隐藏结构承担移动。

### 3. 攻击根不是树冠触手，也不是树干手臂

- 攻击结构本质上仍然是根。
- 攻击根应是**前侧两根较长根须**。
- 它们是“手”的功能，但在造型逻辑上仍属于前侧根系层。

因此：

- 不能从树冠直接长出攻击根。
- 不能从树干中上段长出两条像手臂的攻击根。
- 不能让攻击根漂在树体上半部，脱离根系语义。

## 结构约束

### 1. 树干

- 树干必须明显粗于普通 Minecraft 树。
- 树干下半部必须有更厚的体量，用于过渡到根颈和支撑根。
- 不能出现“细树干插在一团根底座上”的感觉。

### 2. 根颈与连接逻辑

- 树干底部要通过根颈、板根、连接根连续过渡到外圈根。
- 不能出现：
  - 只有部分根接到树干
  - 根像单独摆件一样围着树干摆一圈
  - 树干与根系看起来像两套分离结构

必须满足：

- 可见外圈主根都能在结构上追溯到树干体系。
- 正面和 45 度视角都能看出“树干 -> 连接根 -> 支撑根/普通根”的连续关系。

### 3. 支撑根与普通根的层次

- 支撑根是腿，普通根是辅助层。
- 支撑根必须比普通根更低、更外、更能承担视觉重量。
- 普通根不能和支撑根处在同一高度层，看起来像一圈平铺零件。

### 4. 根须离地空间

- 底部要给根须留出视觉空间。
- 不能让所有根都和地面同高，压成一层。
- 根的最底部要有“继续下探/撑地”的感觉，而不是一条水平边。

## 动画约束

### 1. 行走动画

- 行走动画必须服务于“多根支撑整棵树行走”。
- 不能再回到“两条隐藏腿驱动，其他根只是摆设”的逻辑。
- 支撑根应当参与步态读感，哪怕动作幅度不大，也必须看得出它们是行走结构的一部分。

### 2. 攻击动画

- 攻击动作由**前侧两根较长攻击根**完成。
- 攻击方式是**从上到下的大幅度挥击/砸击**。
- 攻击根必须足够长，并且不能埋进前方根层。
- 攻击时要能清楚看出：
  - 哪两根在打
  - 它们是从前侧根系层抬起再砸下
  - 动作幅度明显，不是轻微摆动
- 实机可读性要求：
  - 攻击动画不能快到肉眼难以分辨
  - 必须能读出“低位待机 -> 上抬离地 -> 下砸/下摆 -> 回到低位”的阶段
  - 如果攻击动作在游戏里看起来像没有挥动，应优先检查动画时长和阶段节奏，而不是继续改静态模型

## 审美与逻辑禁止项

以下情况视为不合格：

- 看起来像树皮人形怪
- 看起来像树干 + 根底座两套分离结构
- 攻击根从树冠长出
- 攻击根从树干中上段长出
- 多根只是装饰，真正走路靠隐藏两条腿
- 所有根都在差不多同一高度层
- 只有部分根接到树干
- 攻击根被前方根层埋住

## 工作流硬门槛

每一轮 WalkingTree 修改必须满足：

1. **先对照本文件确认本轮目标是否违反硬约束**
2. **先改模型，再同步 `bbmodel`**
3. **先跑本地客观审计，再出预览图**
4. **必须有独立 SubAgent 审计**
5. **用户先看图确认结构逻辑，再进游戏**

如果任一环节与本文件冲突，这一轮不得进入游戏测试。

## 当前最重要的总基线

用一句话重新固定：

**行走树是一整棵树，底部多根支撑根就是它的腿；前侧两根较长根须是它的攻击“手”，但本质仍然是根。**
