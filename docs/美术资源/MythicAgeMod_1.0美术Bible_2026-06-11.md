# MythicAgeMod 1.0 美术 Bible

生成日期：2026-06-11

本文档冻结 1.0 的视觉方向。后续生物、建筑、UI、图标、粒子和音效文案都要从这里取样，不允许只为了让资源“存在”而使用随机程序纹理、泛用方块造型或无文明区分的特效。

## 1. 总原则

- 设计先行：先确定体量、轮廓、部件、UV、纹理和动作，再建模。
- Minecraft/Fabric 风格：使用方块化结构，但核心神话特征必须清楚。
- 近读和远读都要成立：近处能看到眼睛、嘴、纹样和材质；远处能看出轮廓和文明归属。
- 不复刻《神话时代》原始资产：只参考单位定位和神话主题，产出原创资产。
- 自动 gate 只检查下限：最终必须看三视角和关键动作，不用脚本代替审美判断。

## 2. 全局比例规则

| 类型 | 视觉高度目标 | 体量规则 |
| --- | --- | --- |
| 小型/矮人/僵尸 | 1.4-2.2 格 | 不能比普通玩家更没特征；头脸和手持物要放大。 |
| 标准人形战士 | 2.2-2.8 格 | 头、肩、武器、胸部符号必须可读。 |
| 大型兽类 | 1.6-2.4 格高，2.0-3.4 格长 | 身体不能臃肿成一块；头、爪、尾、鬃毛要有层次。 |
| 巨人/巨像 | 3.8-4.8 格 | 必须显著高于玩家；腿、肩、武器或胸甲要提供压迫感。 |
| 飞行单位 | 翼展至少大于体宽 2 倍 | 头、翼、尾和骑乘空间不能被翅膀遮没。 |
| 多头/多段单位 | 关键头/段不能小于主体识别阈值 | 多头或多段必须形成清楚节奏，不允许只是一团脖子。 |

## 3. 文明视觉板

### 3.1 Greek

核心词：大理石、青铜、橄榄绿、奥林匹斯、神庙柱式。

| 项目 | 规则 |
| --- | --- |
| 主色 | 白石、暖金、青铜、橄榄绿、深海蓝点缀。 |
| 材质 | 大理石边线、青铜板缝、皮革束带、金属武器、羽毛高光。 |
| 纹样 | 月桂叶、回纹、柱头线条、青铜铆钉。 |
| 生物重点 | 眼睛、嘴、角、蹄、鬃毛、蛇发、多头、翼、武器必须正面可读。 |
| 粒子 | 蓝金雷光、青铜冲击、橄榄绿治愈、冥界紫黑烟。 |
| 禁用 | 纯灰泥块、无面部的大体块、随机噪声纹理、没有武器的人形巨怪。 |

Greek 生物重点：

- Hydra：低伏长身，五头扇形，头和颈比身体更抢眼。
- Cyclops：巨大人形、中央独眼、厚眉骨、嘴、巨大石棒。
- Pegasus：纯白主色，明确马头、耳、鼻口、鬃毛、羽翼、骑乘背线。
- Medusa：凝视眼、嘴、蛇发多头端点、盘绕蛇尾。
- Colossus：青铜面具、发光眼缝、胸甲、王冠和铜绿板缝。

## 4. 模型规则

- 每个模型必须有明确 group 层级，group 名称要能映射到 Java runtime model 部件。
- 头脸类部件要优先占据正面视觉空间；眼睛和嘴不能靠纹理随机落点。
- 武器、翼、尾、角、鬃毛、多头、蛇发等神话特征必须作为独立部件或清楚子部件存在。
- 大型单位不能只整体放大，要增加肩、胸、腿、武器或甲片层次。
- 四足单位至少区分前腿、后腿、爪/蹄、尾，避免普通箱体躯干。
- 飞行单位要区分翼肩、翼骨、羽片/膜片、尾羽或尾鳍。

## 5. 纹理规则

- UV 先行：眼睛、嘴、鼻/吻、角、爪、武器、符号、翼纹、尾端必须固定 UV 区。
- 不允许最终资源使用随机彩色面板或大面积无意义噪声。
- 每个文明建立 8-12 色主调色板，关键材质至少有亮面、暗面和边缘色。
- 纹理必须在 `texture_fit.png` 和三视角预览中检查空白、错位、透明破面。
- 眼睛必须有眼白/瞳孔或发光核心；嘴必须有阴影、牙或唇线之一。

## 6. 动作规则

每个生物必须定义：

- `idle`
- `walk` 或 `run`
- `attack`
- `special`
- `hurt`
- `death`

飞行或骑乘单位额外定义：

- `takeoff`
- `fly`
- `land`
- `riding_fly`

多部件单位额外定义：

- Hydra：多头分时攻击和共同嘶吼。
- Chimera：狮头、羊头、蛇尾联动。
- Manticore：翼展开和蝎尾刺击。
- Medusa：蛇发摆动和凝视锁定。
- Azure Dragon：身段波浪和须摆动。
- Crystal Leviathan：水中滑动和水晶背棘闪烁。

## 7. UI 规则

- 守护者交易 UI 必须展示文明主题背景或边框。
- 神力详情必须展示文明、来源、消耗、冷却、效果、失败原因。
- 证书余额必须从其他输入材料中区分出来。
- 神殿/神像/圣物状态要显示有效/无效、缺失部件、产出倒计时和存储量。
- 文本必须用多语言 key，不把调试中文硬编码进最终 UI。

## 8. 粒子规则

每个神力和核心生物技能使用三段式：

1. 启动：低数量、识别施法源。
2. 持续：展示范围、方向或锁定对象。
3. 命中/结束：高识别度爆发或收束。

性能约束：

- 使用 `MythicParticleEffects` 的密度、距离和上限控制。
- 大范围神力必须有低配可降级方案。
- 不在服务端 tick 内无上限发射粒子。

## 9. 图标和物品规则

- 神力书图标不能只改色；至少包含文明符号和神力语义。
- 证书图标必须体现文明材质和神明/文明符号。
- 圣物图标需要比普通物品更高对比，便于背包中识别。
- Atlantean 当前 MVP 图标要进入独立设计，不长期共享占位风格。

## 10. 人工验收清单

每个生物最终验收必须回答：

- 正面是否能看清眼睛、嘴和最重要神话特征？
- 侧面是否能看清体态、翼、尾、武器或多头结构？
- 45 度是否比正/侧更能展示层次？
- 与玩家相比是否有正确体量？
- 纹理是否有空白、透明破面或关键面错位？
- 动作是否能表达攻击和特殊技能？
- 粒子是否增强技能识别，而不是遮挡模型？
- 是否能一眼归属到对应文明？
